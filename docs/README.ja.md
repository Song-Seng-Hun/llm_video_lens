# LLM Video Lens

動画を、AI（LLM）が読める短い文章と確認用の画像に変えるコマンドラインツールです。ショットに分け、ショットごとに体とカメラがどう動いたかを書き、すべての内容を元のフレーム番号までたどれるように残します。
## なぜ作ったか

AI エージェントは動画を数枚の静止フレームとして見ます。フレームとフレームのあいだに何がどれだけ、どう動いたかは見えないので、動きの向きや大きさをつかむのが難しくなります。速く動き出してゆっくり止まるような緩急（イージング）は特に分かりません。そのため「参考動画の緩急を分析して、同じ感じで動かして」のような作業がとても難しくなります。

LLM Video Lens はそれを助ける補助ツールです。フレーム間の動きを点で追い、向き・距離・速さの変化を文章に書き、軌跡を画像の上に重ねて描きます。これで、数枚のフレームだけでは見落とす動きをエージェントが読めます。

人やキャラクターが映る動画を 1 本入れると、ショット（カット）ごとに体・腕・脚・カメラの動きを短い文章（`look.md`）に書き、確認用の画像も一緒に作ります。確かでない部分をでっち上げることはしません。点を見失った区間は「不明」と書き、推定が揺れたりあいまいだったりする区間は先頭の「먼저 확인할 곳」（先に確認する所）にまとめます。

## 主な機能

- **まとめて要約（`look`）**：動画 1 本を分析し、ショットごとの動きの要約（`look.md`、韓国語で出力）と確認用の画像を作ります。
- **区間を質問（`at`）**：「18〜22 秒に何が起きた？」のように、4 秒以内の区間の根拠だけを集めます。
- **ショットの分割と一覧（`scan`、`brief`、`catalog`）**：カットの境界を見つけ、ショットごとに元のフレーム範囲と欠けた区間を載せた一覧を作ります。
- **フレームの比較（`compare`、`zoom`）**：2 つのフレームの違いを画像で見たり、短い区間を密なフレームで見たりします。
- **点を自分で置く（`grid`、`mark`）**：小道具や、姿勢モデルが名前を知らない部分に点を置き、名前を付けて追跡します。
- **作業フォルダーの外には触れない**：動画を読み、結果を書くのは指定した作業フォルダーだけです。

## クイックスタート

1. Python 3.11 以上で依存パッケージをインストールします（macOS Apple Silicon の Python 3.12 で検証）。`look` は姿勢推定と点の追跡を両方使うので、2 つのセットがどちらも必要です。

   ```sh
   pip install -r requirements/pose.txt -r requirements/tracking.txt
   ```

2. モデルファイルを 3 つ自分で用意します。人物検出（YOLOX HumanArt、ONNX）、全身の姿勢（RTMW 133 キーポイント、ONNX）、点の追跡（CoTracker のチェックポイント）です。リポジトリには入っておらず、自動でダウンロードもしません。
3. 作業スペースのフォルダー（既定はリポジトリ内の `workspace/`）に動画をコピーし、`workspace/models.json` にモデルのパスを書きます。

   ```json
   {"detector": "/models/yolox_humanart.onnx", "pose_model": "/models/rtmw133.onnx", "checkpoint": "/models/scaled_offline.pth"}
   ```

4. リポジトリのフォルダーで実行します。下の `W` は作業スペースのフォルダーのパスです。パッケージとコマンドは最初の名前のまま `image_lens` です。

   ```sh
   python -m image_lens --workspace W look --video clip.mp4 --out look-clip
   ```

5. 出力フォルダーの `look.md` を開きます。先頭の「먼저 확인할 곳」から見てください。

## 使用例

### 動画を 1 本要約して読む

`look.md` は追跡した区間ごとに動きを 1 行にまとめ、各行には次の内容が入ります。

- ショットの構図：全身、膝上、上半身、顔のクローズアップ
- 画面全体（カメラ）と体の中心の動き
- 腕・脚などの部位が体を基準にどう動いたかと、その速さ。例：「속도 9→5→3→1 px/f」
- 点を見失った所、作画が急に変わった所、同じ姿勢が繰り返される所などの注意表示

一緒に作られる画像もあります。

- `…-onion.jpg`：区間ごとに作られるオニオンスキン。最初と最後のフレームを重ね、動きの軌跡と矢印を描いた画像です
- `frame-sheet-N.jpg`：動画全体から均等に選んだフレームの一覧
- `check-sheet-N.jpg`：「먼저 확인할 곳」の区間の密なフレーム

### 結果の例

#### 実写

1 人で踊る実写動画の `look.md` から、膝を上げる区間の 1 行を取り出しました（長いので一部を `…` で省略）。出力の文章は韓国語です。

```text
- 15.44–16.32s f386..407 | 전신 | 정면(사람 왼쪽=화면 오른쪽) | 팔 자세: 왼팔 가슴 높이·오른팔 허리 아래 그대로 | 전체: 카메라 모름(5%만 맞춤), 몸 왼쪽 아래 33px(속도 2.5→2.2→1.6→1.4→0.8 px/f) | 몸 기준: 오른다리(화면 왼쪽: 발목·무릎·허벅지) 오른쪽 위 147px(속도 13.3→13.3→12.2→10.4→10.2 px/f, 앞선 동작은 모름) → 오른쪽 51px(속도 9.2→7.3→5.8→6 px/f), 몸 바깥으로; 왼다리(화면 오른쪽: 허벅지·발목·무릎) 위 74px(…), 몸 쪽으로; … | 높이별(화면 좌표, 카메라 모름): 왼쪽 아래 33 / ? / 왼쪽 위 25 / 오른쪽 위 45 / 오른쪽 아래 14 (…) | 몸 돌림 후보(어깨 폭 크게 변함, 포즈가 튄 것일 수도; 그동안 어깨 높이는 안 씀): 15.44–15.88s | …
```

- `15.44–16.32s f386..407`：時間と元のフレーム番号。この番号で元動画をたどれます。
- `전신`（全身）、`정면(사람 왼쪽=화면 오른쪽)`（正面、本人の左＝画面の右）：構図と体の向き。以降の左右は本人の体が基準で、括弧内が画面上の側です。
- `팔 자세`（腕の姿勢）：区間の最初と最後の手首の高さ。この区間では変わりません（`그대로`）。
- `전체`（全体）：カメラと体の中心の動き。背景が無地なのでカメラは「모름」（不明）で、体の中心は左下へ 33px 動きました。速さの数字が小さくなるのは、だんだん遅くなったという意味です。
- `몸 기준`（体基準）：体の中心の動きを除いた手足の動きで、矢印は時間の順です。右脚が右上へ 147px 上がり、さらに右へ 51px 出ました。膝を上げる動作です。
- `높이별`（高さ別）：人物が写っている範囲を上から下へ 5 段に分けて測った動き。`?` はその段を測れなかったという意味です。
- `몸 돌림 후보`（体の回転の候補）：推定が揺れたため、確認が必要だと印を付けた所です。

<p align="center"><img src="../assets/example-onion.jpg" width="560" alt="look が作ったオニオン画像。左は開始フレーム（シアン）と終了フレーム（赤）を重ねたもので、黄色い点線が右脚に沿って下から膝の高さへ弧を描いて上がり、緑の矢印が高さ別の動きを示します。右はスペーシングチャートです。"></p>

同じ区間のオニオンスキンです。左は開始（シアン）と終了（赤）を重ねたものです。点線は `몸 기준` に書かれた順に、黄（右脚）・マゼンタ（左脚）・青（左腕）…の部位の軌跡です。点 1 つが 1 フレームで、少し大きい点は 0.1 秒ごとに付くので、その間隔が詰まれば遅くなったということです。丸が開始、四角が終了です。緑の矢印は `높이별` の動きです。右端はスペーシングチャートで、部位ごとの移動経路を同じ長さの線に伸ばし、0.1 秒ごとに太い目盛りを付けたものです。目盛りが詰まれば遅く、開けば速いので、少しだけ動いた部位の緩急もここで読めます。

なお、この例でもツールが取り違えたところがあります。脚を上げるときに肩幅が変わったため、実際には体を回していないのに「몸 돌림 후보」が付きました。左腕の速さも「모름」と出ています。

動画の出典：Antoni Shkraba、[「Video of a Man Dancing」](https://www.pexels.com/video/video-of-a-man-dancing-7571381/)、Pexels（[Pexels ライセンス](https://www.pexels.com/license/)）。0〜20 秒を切り出して 1280×674 に縮小し、`look` で作った画像です。

### 気になる区間だけを聞く

要約だけでは足りないときは、気になる区間（4 秒以内）だけを詳しく見られます。

```bash
python -m image_lens --workspace W at --look W/look-clip --span 18-22 --out W/at-18-22
```

`at.md` にはその区間にかかる行と表示、開くべき画像の名前が集まり、`at-frames-1.jpg` には密なフレーム 12 枚が入ります。

### 姿勢モデルが知らない部分を追跡する

`grid` で座標の目盛りを描いたフレームを見て、`mark` で点を置いて追跡します。点は最大 8 個まで置け、名前は ASCII で付けます。

点は 2 本の線が交わる角か、小さな模様（目、ボタン）に置きます。まっすぐな線の途中や単色の面に置くと、線に沿った動きを見落とします。結果の図（`mark-onion.jpg`）で開始と終了の輪郭線は大きく離れているのに点線の軌跡だけが短ければ、途中で追跡がずれています。その点をはっきりした角に置き直して、もう一度試してください。

```bash
python -m image_lens --workspace W grid --video V --frame 572 --box 100,250,1000,1000 --out W/grid-f572.jpg
python -m image_lens --workspace W mark --video V --shots W/look/shots.json --frame 572 --end 599 --point hammer-stripe=430,680 --point eye=322,738 --checkpoint C --out W/mark-s19
```

## 現在の状態と限界

- 手足の位置は姿勢モデルと点の追跡を合わせて推定し、確かでないところは「모름」（不明）と書きます。詳しい比較と限界は [look ノート](look-notes.md) にあります。
- 検証した環境は macOS arm64 の Python 3.12 です。Windows での動作とインストールしたパッケージ（wheel）の実行は未検証で、点の追跡には POSIX 環境が必要です。
- 姿勢、動作、同じ人物かどうかの判定、緩急（easing）が正確であるとは保証しません。「먼저 확인할 곳」にない区間も間違っていることがあるので、フレームシートも合わせて見てください。
- モデルファイルは自分で用意する必要があります。CoTracker のソースとチェックポイントには非商用の利用条件があり、姿勢モデルの重みのライセンスは確認されていません。
- 1920×1080 より大きい動画は縮小してから処理します。このときレポートの px の値は縮小した動画が基準です。

## AIと一緒に作ったプロジェクト

方向は人が決め、AIエージェントたちが一緒に作ったプロジェクトです。何を作るか、どの精度を目指すか、何を採用するかは人が決め、実装・計測・コードレビューは Claude（Anthropic）と Codex（OpenAI）のエージェントが分担しました。[look ノート](look-notes.md)はその過程でエージェントが残した計測記録です。
