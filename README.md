# LLM Video Lens

영상을 AI(LLM)가 읽을 수 있는 움직임 요약과 확인용 그림으로 바꿔 주는 CLI 도구입니다. 샷을 나누고, 샷마다 몸과 카메라가 어떻게 움직였는지 적으며, 모든 내용을 원본 프레임 번호로 되짚을 수 있게 남깁니다.

## 왜 만들었나요

AI 에이전트는 영상을 몇 장의 정지 프레임으로 봅니다. 프레임과 프레임 사이에 무엇이 얼마나 어떻게 움직였는지는 보지 못해서, 동작의 방향과 크기를 파악하기 어렵습니다. 빠르게 출발해 천천히 멈추는 완급(ease)은 특히 알기 어렵습니다. 그래서 "참고 영상의 완급을 분석해서 같은 느낌으로 움직여 줘" 같은 작업이 매우 어렵습니다.

LLM Video Lens는 이를 돕는 보조 도구입니다. 프레임 사이의 움직임을 점으로 따라가 방향, 거리, 속도 변화를 글로 적고, 궤적을 그림 위에 겹쳐 그립니다. 에이전트가 프레임 몇 장만 봐서는 놓치는 움직임을 이렇게 읽을 수 있습니다.

사람이나 캐릭터가 나오는 영상 하나를 넣으면, 샷(컷)마다 몸·팔·다리·카메라의 움직임을 짧은 글(`look.md`)로 적고 확인용 그림을 함께 만듭니다. 확실하지 않은 부분은 지어내지 않습니다. 점을 놓친 구간은 "모름"으로 적고, 추정이 흔들리거나 애매한 구간은 맨 위 "먼저 확인할 곳"에 모읍니다.

## 주요 기능

- **한 번에 요약 (`look`)**: 영상 하나를 분석해 샷별 움직임 요약(`look.md`, 한국어로 출력)과 확인용 그림을 만듭니다.
- **구간 질문 (`at`)**: "18~22초에 무슨 일이 있었지?"처럼 4초 이내 구간의 근거만 모아 줍니다.
- **샷 나누기와 목록 (`scan`, `brief`, `catalog`)**: 컷 경계를 찾고, 샷마다 원본 프레임 범위와 빠진 구간을 담은 목록을 만듭니다.
- **프레임 비교 (`compare`, `zoom`)**: 두 프레임의 차이를 그림으로 보거나, 짧은 구간을 촘촘한 프레임으로 봅니다.
- **직접 점 찍기 (`grid`, `mark`)**: 소품이나 옷자락처럼 자세 모델이 잡지 못하는 곳에 직접 점을 찍고 이름을 붙여 추적합니다.
- **작업 폴더 밖은 건드리지 않음**: 영상을 읽고 결과를 쓰는 곳은 지정한 작업 폴더뿐입니다.

## 빠른 시작

1. Python 3.11 이상에서 필요한 패키지를 설치합니다(macOS Apple Silicon, Python 3.12에서 검증). `look`은 자세 추정과 점 추적을 함께 쓰므로 두 패키지 목록을 모두 설치해야 합니다.

   ```sh
   pip install -r requirements/pose.txt -r requirements/tracking.txt
   ```

2. 모델 파일 세 개를 직접 준비합니다. 사람 검출(YOLOX HumanArt, ONNX), 전신 자세(RTMW 133 키포인트, ONNX), 점 추적(CoTracker 체크포인트)입니다. 저장소에 들어 있지 않고, 자동으로 내려받지도 않습니다.
3. 작업 공간 폴더(기본값은 저장소 안의 `workspace/`)에 영상을 복사하고, `workspace/models.json`에 모델 경로를 적습니다.

   ```json
   {"detector": "/models/yolox_humanart.onnx", "pose_model": "/models/rtmw133.onnx", "checkpoint": "/models/scaled_offline.pth"}
   ```

4. 저장소 폴더에서 실행합니다. 아래의 `W`는 작업 공간 폴더 경로입니다. 초기 프로젝트 이름을 그대로 유지하고 있어, 패키지명과 실행 명령은 `image_lens`입니다.

   ```sh
   python -m image_lens --workspace W look --video clip.mp4 --out look-clip
   ```

5. 결과 폴더의 `look.md`를 엽니다. 맨 위 "먼저 확인할 곳"부터 보세요.

## 사용 예

### 영상 하나를 요약해서 읽기

`look.md`는 추적한 구간마다 한 줄씩 움직임을 요약하며, 각 줄에는 다음 내용이 담깁니다.

- 샷 구도: 전신, 무릎 위, 상반신, 얼굴 클로즈업
- 화면 전체(카메라)와 몸 중심의 움직임
- 몸 중심을 기준으로 본 팔·다리의 움직임과 속도. 예: "속도 9→5→3→1 px/f"
- 점을 놓친 곳, 작화가 갑자기 바뀐 곳, 같은 자세가 반복되는 곳 같은 주의 표시

함께 만들어지는 그림도 있습니다.

- `…-onion.jpg`: 구간마다 만들어지는 어니언 스킨. 첫 프레임과 마지막 프레임을 겹치고 움직임의 궤적과 화살표를 그린 그림입니다.
- `frame-sheet-N.jpg`: 영상 전체에서 고르게 뽑은 프레임 모음
- `check-sheet-N.jpg`: "먼저 확인할 곳" 구간의 촘촘한 프레임

### 결과 예시

#### 실사

혼자 춤추는 실사 영상의 `look.md`에서 무릎을 드는 구간 한 줄을 가져왔습니다(길어서 일부를 `…`로 줄임).

```text
- 15.44–16.32s f386..407 | 전신 | 정면(사람 왼쪽=화면 오른쪽) | 팔 자세: 왼팔 가슴 높이·오른팔 허리 아래 그대로 | 전체: 카메라 모름(5%만 맞춤), 몸 왼쪽 아래 33px(속도 2.5→2.2→1.6→1.4→0.8 px/f) | 몸 기준: 오른다리(화면 왼쪽: 발목·무릎·허벅지) 오른쪽 위 147px(속도 13.3→13.3→12.2→10.4→10.2 px/f, 앞선 동작은 모름) → 오른쪽 51px(속도 9.2→7.3→5.8→6 px/f), 몸 바깥으로; 왼다리(화면 오른쪽: 허벅지·발목·무릎) 위 74px(…), 몸 쪽으로; … | 높이별(화면 좌표, 카메라 모름): 왼쪽 아래 33 / ? / 왼쪽 위 25 / 오른쪽 위 45 / 오른쪽 아래 14 (…) | 몸 돌림 후보(어깨 폭 크게 변함, 포즈가 튄 것일 수도; 그동안 어깨 높이는 안 씀): 15.44–15.88s | …
```

- `15.44–16.32s f386..407`: 시간과 원본 프레임 번호. 이 번호로 원본을 되짚을 수 있습니다.
- `전신`, `정면(사람 왼쪽=화면 오른쪽)`: 구도와 몸 방향. 이후의 왼/오른은 사람 자신의 몸 기준이고, 괄호 안이 화면 쪽입니다.
- `팔 자세`: 구간 처음과 끝의 손목 높이. 이 구간에서는 그대로입니다.
- `전체`: 카메라와 몸 중심의 이동. 배경이 민무늬라 카메라는 "모름"이고, 몸 중심은 왼쪽 아래로 33px 갔습니다. 속도 숫자가 작아지면 점점 느려졌다는 뜻입니다.
- `몸 기준`: 몸 중심을 뺀 팔다리의 움직임으로, 화살표는 시간 순서입니다. 오른다리가 오른쪽 위로 147px 올라간 뒤 오른쪽으로 51px 더 나갔습니다. 무릎을 드는 동작입니다.
- `높이별`: 인물이 잡힌 영역을 위아래 5칸으로 나눠 높이별로 잰 이동입니다. `?`는 그 칸을 재지 못했다는 뜻입니다.
- `몸 돌림 후보`: 추정이 흔들려 직접 확인이 필요하다고 표시한 곳입니다.

<p align="center"><img src="assets/example-onion.jpg" width="560" alt="look이 만든 어니언 그림. 왼쪽은 시작 프레임(청록)과 끝 프레임(빨강)을 겹친 것으로, 노랑 점선이 오른다리를 따라 아래에서 무릎 높이로 휘어 올라가고 초록 화살표가 높이별 이동을 가리킵니다. 오른쪽은 부위별 스페이싱 차트입니다."></p>

같은 구간의 어니언 스킨입니다. 왼쪽은 시작(청록)과 끝(빨강)을 겹친 것입니다. 점선은 `몸 기준`에 적힌 순서대로 노랑(오른다리), 자홍(왼다리), 파랑(왼팔)… 부위의 궤적입니다. 점 하나가 한 프레임이고, 조금 큰 점은 0.1초마다 찍혀서 그 간격이 좁아지면 느려진 것입니다. 원은 시작, 네모는 끝입니다. 초록 화살표는 `높이별` 이동입니다. 오른쪽은 스페이싱 차트로, 부위마다 지나온 길이를 같은 길이의 줄로 펼치고 0.1초마다 굵은 눈금을 찍은 것입니다. 눈금이 모이면 느리고 벌어지면 빠르므로, 조금만 움직인 부위의 완급도 여기서 읽을 수 있습니다. 차트 아래의 작은 그림은 그 구간 첫 프레임 전체이고, 노란 테두리가 어니언이 잘라 보여 준 범위입니다.

참고로 이 예시에서도 도구가 헷갈린 부분이 있습니다. 다리를 들 때 어깨 폭이 변해서, 실제로는 몸을 돌리지 않았는데 "몸 돌림 후보"로 표시되었습니다. 왼팔의 속도도 "모름"으로 나왔습니다.

2D 일러스트·애니메이션 캐릭터도 같은 방법으로 읽습니다. 모자 챙에 댄 손을 바깥으로 쓸어 내며 고개를 갸웃하는 1.5초 동작으로, 이 동작의 완급은 다른 참고 영상에서 이 도구로 잰 속도 변화를 따라 만들었습니다. 손끝의 두 점(자홍, 노랑)이 나란한 호를 그리고, 모자와 얼굴의 윤곽이 갈라진 만큼 머리가 기울었습니다. 오른쪽 스페이싱 차트에서는 손끝 두 줄의 눈금이 처음에 모였다가 가운데서 벌어지고 끝에서 다시 촘촘해집니다. 멈춰 있다가 빠르게 나간 뒤 서서히 멈췄다는 뜻입니다. `몸 기준`에는 왼팔이 오른쪽으로 124px 빠르게 나간 뒤 68px 더 가며 느려졌다고 적힙니다. 배경이 민무늬라 카메라는 "모름"입니다.

### 궁금한 구간만 묻기

요약만으로 부족할 때는 궁금한 구간(4초 이내)만 따로 자세히 볼 수 있습니다.

```bash
python -m image_lens --workspace W at --look W/look-clip --span 18-22 --out W/at-18-22
```

`at.md`에 그 구간에 걸친 줄과 표시, 열어 볼 그림 이름이 모이고, `at-frames-1.jpg`에 촘촘한 프레임 12장이 담깁니다.

### 소품이나 세부 부위 직접 추적하기

소품이나 옷자락처럼 자세 모델이 잡지 못하는 곳은 `grid`로 좌표 눈금을 그린 프레임을 보고, `mark`로 점을 찍어 추적합니다. 점은 최대 8개까지 찍을 수 있고, 이름은 ASCII로 붙입니다.

점은 두 선이 만나는 모서리나 작은 무늬(눈, 단추)에 찍습니다. 곧은 선의 가운데나 단색 면에 찍으면 선을 따라가는 움직임을 놓칩니다. 결과 그림(`mark-onion.jpg`)에서 시작과 끝의 윤곽선은 크게 벌어졌는데 점선 궤적만 짧다면, 중간에 추적이 미끄러진 것입니다. 이럴 때는 그 점을 뚜렷한 모서리로 옮겨 다시 찍어 보세요.

```bash
python -m image_lens --workspace W grid --video V --frame 572 --box 100,250,1000,1000 --out W/grid-f572.jpg
python -m image_lens --workspace W mark --video V --shots W/look/shots.json --frame 572 --end 599 --point hammer-stripe=430,680 --point eye=322,738 --checkpoint C --out W/mark-s19
```

## 현재 상태와 한계

- 팔다리 좌표는 자세 모델과 점 추적을 함께 써서 추정하고, 확실하지 않은 곳은 "모름"으로 적습니다. 자세한 비교와 한계는 [look 노트](docs/look-notes.md)에 있습니다.
- 검증한 환경은 macOS arm64의 Python 3.12입니다. Windows에서의 동작과 설치한 패키지(wheel) 실행은 검증되지 않았고, 점 추적에는 POSIX 환경이 필요합니다.
- 자세와 동작, 같은 사람인지의 판별, 완급(easing)이 정확하다고 보장하지 않습니다. "먼저 확인할 곳"에 없는 구간도 틀릴 수 있으니 프레임 시트를 함께 보세요.
- 모델 파일은 직접 준비해야 합니다. CoTracker 소스와 체크포인트에는 비상업적 이용 조건이 있고, 자세 모델 가중치의 라이선스는 확인되지 않았습니다.
- 1920×1080보다 큰 영상은 줄여서 처리합니다. 이때 보고서의 px 값은 줄인 영상 기준입니다.

## AI와 함께 만든 프로젝트

이 프로젝트는 사람이 방향을 정하고 AI 에이전트들이 함께 만든 결과물입니다. 무엇을 만들지, 어떤 정확도를 목표로 할지, 무엇을 채택할지는 사람이 정했고, 구현·측정·코드 리뷰는 Claude(Anthropic)와 Codex(OpenAI) 에이전트가 나눠 맡았습니다. [look 노트](docs/look-notes.md)는 이 과정에서 에이전트가 남긴 측정 기록입니다.
